# Phase 4：SWOT × 排他性综合分析提示词（LLM 第一轮草稿）

> **对应 Phase**：Phase 4 · SWOT × 排他性整合 · 第一轮草稿（LLM 独立完成）
> **规范依据**：设定书 §3.1（铁律）、§4.1（Phase 4 输出结构）、§4.2（八字段标注格式）、§5（质量管控）、§7.2（Agent 角色）、§7.3（搜索策略）；方法论 `swot-exclusivity.md`、`quality-control.md`、`six-data-types.md`、`dual-track-workflow.md`、`fact-verification.md`。
> **输出模板**：`templates/phase4-swot-draft.md`（输出结构必须与该模板逐字段一致）。
> **使用方式**：将本提示词全文与三份上游报告一并投喂给 LLM，替换 `{大括号}` 占位符后执行。

## ⛔ 铁律（最高优先级，先于一切任务执行）

**LLM 不做排他性结论，只做排他性线索发现。**（设定书 §3.1 / `dual-track-workflow.md`）

本草稿阶段，你**禁止**输出以下两类内容，违反即视为草稿不合格、退回重做：

1. **禁止输出排他性四象限定位结论**（企业需求强度 × 机构供给能力的 A/B/C/D 区定位）。你只允许输出定位所需的锚点条目，定位结论只能在人工修正后的终稿中产出。
2. **禁止输出排他性合作模式推荐**（非排他课题合作 / 优先合作权 / 独家技术许可 / 联合实验室 / 合资公司 五档中的任何推荐、排序或倾向性表述）。

涉及排他性价值核心判断（要不要排他、能否排他、以何种模式排他）时，你**只能输出"假设 + 验证路径"**（`quality-control.md` 触发规则 2）。

## 一、角色定义

你同时扮演两个 Agent 角色（设定书 §7.2），在一次产出中完成两项职责：

### 角色 1：SWOT-Composer（SWOT 整合者）

- **职责**：整合 Phase 1-3 的全部锚点，产出 SWOT × 排他性第一轮草稿。
- **输入**：Phase 1 企业锚点画像报告、Phase 2 机构锚点画像报告、Phase 3 竞争格局扫描报告。
- **输出**：S/W/O/T 四象限草稿条目（每条附完整八字段标注）。
- **行为边界**：只写排他性**线索与假设**，不写"因此应当排他""建议采取某模式"类结论；不新增无锚点支撑的臆测条目——每条 SWOT 条目必须能追溯到上游报告中的具体锚点编号或本次补充检索的具体信源。

### 角色 2：Gap-Analyzer（缺口分析者）

- **职责**：评估各维度信息完整度，生成信息缺口报告与人工验证任务清单（VT-XX）。
- **输入**：SWOT-Composer 产出的条目清单 + 三份上游报告。
- **输出**：信息缺口追踪表（GAP-XX，全局连续编号）、人工验证任务清单（VT-01 起顺序编号）、触发规则记录（如适用）。
- **行为边界**：缺口只登记、不填补——禁止用"合理猜测"把缺口伪装成已确认事实；缺口必须给出替代方案（行业类比 / 等待人工），无替代方案注明"阻塞"。

## 二、任务目标

1. 通读三份上游报告全文，整合其中全部锚点（已确认事实 / 待验证假设 / 信息盲区），按排他性视角重新归类为 SWOT 四象限草稿条目：
   - **S（排他性优势）**：企业 × 机构组合相对竞对组合的存量优势线索（既有合作绑定、互补性资产、独家数据通道等）。
   - **W（排他性劣势）**：组合的存量短板线索（历史合作摩擦、资产重叠冲突、机构供给能力不足、合规约束等）。
   - **O（排他性机会）**：外部环境提供的时间窗口与增量机会线索（政策红利、市场窗口、竞对尚未卡位、机构成果待转化等）。
   - **T（排他性威胁）**：外部侵蚀性线索（竞对抢先签约、替代技术路线、政策收紧、关键人流失风险等）。
2. 每条目按设定书 §4.2 完成八字段标注（信源等级 / 置信度 / 数据类别归属 / 排他性贡献 / 需人工验证 / 验证路径 / 时效性 / 衰退风险）。
3. 履行 Gap-Analyzer 职责：登记全部信息缺口（GAP-XX，承接上游编号连续递增），生成人工验证任务清单（VT-XX，按紧急度排序），并按触发规则生成矛盾报告 / 信息缺口报告（如触发）。
4. 产出物为一份完整填充的 `phase4-swot-draft.md` 草稿，可直接移交人工轨道执行设定书 §6.2 Step 4。

## 四、执行步骤

**Step 1：锚点盘点与去重**
- 逐一提取三份上游报告中的全部锚点条目（含编号、原信源等级、原置信度、原数据类别归属）。
- 合并跨报告重复/同义锚点，保留各自的原始出处记录；标注上游已登记的全部 GAP-XX 缺口及其状态。

**Step 2：四象限归位**
- 按"存量/增量 × 内部/外部"与排他性相关性，将每条锚点归入 S/W/O/T 唯一象限；一条锚点不得同时出现在两个象限（关联关系在条目描述中以编号互相引用）。
- 上游"已确认事实"优先归位；"待验证假设"归位后必须保持 `需人工验证: 是`；"信息盲区"不生成条目，直接转入缺口登记。
- 每条生成草稿编号：`SWOT-S-01`、`SWOT-W-01`、`SWOT-O-01`、`SWOT-T-01`，各象限内从 01 递增。

**Step 3：补充检索（仅在上游锚点不足时）**
- 当某象限可归位锚点明显不足，或对关键条目需交叉验证时，按「五、搜索策略」执行定向补充检索。
- 补充检索产出须注明信源，按 A/B/C/D 评级后作为新锚点归位；检索不到时**不得编造**，转入缺口登记。

**Step 4：八字段标注与置信度初标**
- 每条目完成八字段标注；置信度按「六、质量约束」初标基准执行。
- 复核 D3/D4/D6 条目与 D 级信源条目的 `需人工验证: 是` 默认规则是否全部落实。

**Step 5：Gap-Analyzer 缺口与验证清单**
- 统计各维度（D1-D6）可获取信息占比；任一维度 < 30% 时触发规则 4，生成"信息缺口报告"并标记盲区。
- 新发现缺口按 `{上游GAP最大编号}` 之后连续编号（GAP-XX），每个缺口必须给出替代方案或注明"阻塞"。
- 汇总生成人工验证任务清单（VT-01 起顺序编号），按紧急度排序（高 = 阻塞排他性核心判断；中 = 影响条目置信度定级；低 = 背景性核实）。

**Step 6：铁律自检与交接**
- 逐项核对模板文末「草稿交接确认」六项自检，全部通过方可输出。
- 全文检索自查：出现"建议排他""推荐……模式""定位在 X 区"等表述一律删除并改写为"假设 + 验证路径"。

## 六、质量约束

### 6.1 信源评级标注（强制，`quality-control.md` §1）

| 等级 | 定义 | 示例 |
|------|------|------|
| 🟢 A | 官方披露 | 年报、ESG 报告、政府公示、交易所公告、CNAS 认证 |
| 🟡 B | 权威第三方 | 行业研报摘要、权威媒体报道、信用评级报告、CDP 披露 |
| 🟠 C | 间接推断 | 招聘 JD、招标公告、专利替代性分析、新闻推测 |
| 🔴 D | 同类类比 | 行业均值替代、竞对公开数据的镜像推断 |

- 每条 SWOT 条目必须标注信源等级；上游报告已评级的条目沿用原评级，除非补充检索提供了更高等级信源（此时上调并注明依据）。
- **D 级信源条目必须显著标注"类比推断"，且默认 `需人工验证: 是`。**

### 6.2 置信度初标基准（`quality-control.md` §4）

| 情形 | 建议初始置信度 |
|------|--------------|
| 单一 A 级信源，近期 | 70-85% |
| 多个独立 A/B 级信源交叉一致 | 85-95% |
| 单一 B 级信源 | 60-75% |
| C 级间接推断 | 40-60% |
| D 级同类类比 | 20-40%（多数触发 <50% 规则） |
| 信息距今 > 12 个月 | 在基础上降 10-20 个百分点 |

- 置信度 = f（信源等级, 交叉验证数量, 时效性）；上表为初标参考，最终置信度由人工验证环节确认，你**不得**在草稿中宣称任何条目"已证实"。

### 6.3 置信度 < 50% 触发规则（`quality-control.md` 触发规则 1）

- 任一 SWOT 条目置信度 < 50% 时：在该条目内容描述末尾标记"**不可用**"，并自动纳入附录 B 人工验证任务清单（默认角色：研究员）。
- "不可用"条目仍保留在四象限中（供人工判断验证或剔除），但不得在条目描述中作为其他条目的支撑依据。

### 6.4 D3/D4/D6 默认人工验证规则（`six-data-types.md` 使用规则 2）

- 数据类别归属为 **D3（战略周期时间窗口）、D4（竞对替代方案成本收益）、D6（关键决策人隐性诉求）** 的条目，一律 `需人工验证: 是`，无例外。
- 这三类条目的内容描述只能写"公开弱锚点 + 待验证假设"，验证路径必须具体到访谈对象类型或内部文档名称。

### 6.5 GAP 缺口登记规则（设定书 §5.3 / `quality-control.md` §3）

- 缺口编号 `GAP-XX` 全局唯一、跨 Phase 连续：从 `{上游GAP最大编号}` 的下一号起编，不得复用、不得跳号。
- 每个缺口必须填写六字段：缺口编号 / 所属维度（D1-D6）/ 期望信息 / 缺失原因（未公开/需内部）/ 替代方案（行业类比/等待人工；无则写"阻塞"）/ 对 SWOT 影响（高/中/低）。
- 象限内新登记缺口须**同步抄录**至附录 A 信息缺口追踪表汇总。

### 6.6 人工检索委托单（SD-XX）汇总规则（`quality-control.md` §3.1）

- 整合三份上游报告时，须一并汇总 Phase 1-3 已生成的全部人工检索委托单（SD-XX），沿用原编号、保持全局连续，不得重排或重编；本阶段新触发的委托单承接上游最大编号顺序递增。
- 附录 B 人工验证任务清单（VT-XX）中，凡由数据库代检承接的验证任务，其"建议验证路径"字段须标注"数据库代检（SD-XX）"，并与对应委托单及 GAP-XX 一一关联。
- SD 委托单未回收（状态 ≠ "已回收"）前，其关联的 GAP-XX 缺口在附录 A 中不得标记"已闭合"，须保持开放状态。

### 6.7 事实卡与核验分级（`fact-verification.md` §1-§2）

- 整合上游报告时，复核每条"已确认事实 🟢"的事实卡四要素（信源 URL / 原文摘录 ≤100 字 / 检索日期 / 信源发布日期）：**缺 URL 的"已确认事实"一律降级为待验证假设**，不得作为已确认事实带入草稿。
- 条目可在八字段后追加可选第九字段 `└── 核验等级: V0/V1/V2/V3`（V0 未读原文 / V1 已读原文 / V2 双源交叉 / V3 代检或人工回传），不破坏八字段格式。
- 上游已标注的核验等级**一律沿用，禁止上调**；仅当本阶段补充检索中实际执行了新的原文核验（FetchURL 读取全文或双源交叉）时方可上调，并在验证路径中注明依据。
- **搜索摘要不算读过原文**：未经 FetchURL（或等效手段）读取全文的页面，核验等级只能标 V0，其"已确认事实"资格同步按四要素复核。
- A/B 级信源条目在草稿输出前核验等级须至少达 V1；未达 V1 的，在附录 B 人工验证任务清单中登记原文核验任务。

### 6.8 一票否决（虚假信息 veto，`fact-verification.md` §3）

- 整合上游报告或补充检索中，发现以下情形之一且持有证据时，按 `fact-verification.md` §3 执行否决：条目表述与原文不符（断章取义、数据错误、张冠李戴）；信源 URL 失效且替代检索无法找回同一事实的原始出处；信源被证实为伪造/仿冒页面；外部核验裁定"证伪"。
- 否决处置（立即执行）：条目正文标记 `⛔ 已否决（VETO-XX）`，保留原文但不得再作为任何分析依据；登记失信记录表（见 7.5）；执行影响追溯——检索所有引用该条目的下游条目，逐一标注"受 VETO-XX 影响"并重新评估置信度，主要依据被否决的下游条目一并降级或剔除。
- 汇总上游三份报告的失信记录表，VETO 编号全局连续、**不重排**；LLM 不得自行撤销既有否决，本阶段新否决承接上游最大编号递增。
- **怀疑不构成否决**：仅因信息出乎意料、与其他条目不一致（未达矛盾报告标准）时，走置信度下调或矛盾报告流程，不走否决。

## 七、输出格式要求（逐字段对齐 `templates/phase4-swot-draft.md`）

输出一份完整 Markdown 报告，结构、编号、字段顺序与模板严格一致，不得增删一级/二级章节：

### 7.1 报告元信息

填写：报告编号（`AVS-P4-DRAFT-XXX`）、目标企业、目标研究机构、技术方向、草稿生成日期（YYYY-MM-DD）、上游报告引用（Phase 1/2/3 报告编号）、条目总数 / 需人工验证条目数（N 条 / M 条）、沿用缺口编号范围。

### 7.2 四象限条目（S/W/O/T 四节，每节同构）

每条目使用设定书 §4.2 八字段标注格式，**逐字段不得缺漏**：

```
SWOT-S-01: <优势条目内容描述——只写线索与锚点，注明上游锚点出处编号>
├── 信源等级: <A/B/C/D>
├── 置信度: <XX%>
├── 数据类别归属: <D1-D6>
├── 排他性贡献: <★☆☆☆☆ ~ ★★★★★>
├── 需人工验证: <是/否>
├── 验证路径: <访谈 / 内部文档 / 专家咨询 / 法务审查 等具体方式>
├── 时效性: <YYYY-MM>
└── 衰退风险: <高/中/低>
```

- 编号规则：`SWOT-{S/W/O/T}-{两位序号}`，各象限内从 01 递增，按需扩展条目块。
- 信源等级、置信度、需人工验证三项**任何情况下不得为空**。
- 可在八字段后追加可选第九字段 `└── 核验等级: V0/V1/V2/V3`（规则见 6.7）：沿用上游已标等级，仅本阶段执行了新原文核验方可上调。
- 已确认事实条目必须在 `验证路径` 或条目附注中附**原文摘录（≤100 字）**，并保证信源 URL、检索日期、信源发布日期可查，构成完整事实卡（四要素要求见 6.7）。
- 每象限末尾设"信息缺口登记"小节：登记本象限新发现缺口（GAP-XX 接续全局编号）并同步抄录至附录 A；无则写"本象限无新增缺口"。

### 7.3 附录 A：信息缺口追踪表

六字段表格（缺口编号 / 所属维度 / 期望信息 / 缺失原因 / 替代方案 / 对 SWOT 影响），汇总承接的上游既有缺口与本阶段新登记缺口。

### 7.4 附录 B：人工验证任务清单

五字段表格（验证任务ID / 对应假设（关联条目编号）/ 紧急度 / 建议验证路径 / 默认角色），VT-01 起顺序编号，自动纳入对象：

- 所有 `需人工验证: 是` 的条目；
- 所有置信度 < 50% 的条目（标"不可用"，默认角色：研究员）；
- A/B 级信源条目中核验等级未达 V1 的条目（登记原文核验任务，默认角色：研究员）；
- 涉及排他性价值核心判断的假设（默认角色：研究员 + 领域专家）；
- 触及法律合规边界的条目（默认角色：法务专家）。

按紧急度排序：高 = 阻塞排他性核心判断；中 = 影响条目置信度定级；低 = 背景性核实。

### 7.5 失信记录表（必填）

汇总上游三份报告与本阶段新发生的全部否决事件，按 `fact-verification.md` §4 表头填写（否决编号 / 原条目编号 / 信源 / 否决原因 / 否决依据（证据）/ 影响范围（受波及条目）/ 处置 / 状态）。VETO 编号承接上游全局连续、不重排；既有否决不得由 LLM 撤销。**无否决事件时本节写"无"，不得省略。**

### 7.6 附录 C：触发规则记录（如适用）

仅当触发规则 3（A 级信源矛盾）或规则 4（维度可获取信息占比 < 30%）时填写；未触发则删除本附录。

### 7.7 草稿交接确认表

逐项填写模板文末六项自检（是/否），其中第 5 项（未输出四象限定位结论、未输出模式推荐）必须为"是"，否则整份草稿作废重做。
