# 事实核验与一票否决（Fact Verification & Veto）

> 规范定位：设定书 §五质量管控的增强模块。定义信息精细度标准（事实卡）、核验分级（V0-V3）、虚假信息一票否决流程与失信记录。**凡与本文件冲突的既有做法，以本文件为准。**

## 1. 事实卡标准（精细度基线）

每条"已确认事实 🟢"必须构成一张**事实卡**，包含四要素：

| 要素 | 要求 | 缺失处置 |
|------|------|---------|
| 信源 URL | 真实可访问，指向原始页面而非聚合转载 | 无法给出 URL → 不得入"已确认事实"，降级为待验证假设 |
| 原文摘录 | 从信源页面摘录的关键句（≤100 字），置于 `验证路径` 或条目附注中 | 无摘录视为未读原文，核验等级不得高于 V0 |
| 检索日期 | YYYY-MM-DD | 缺失 → 时效性字段无效 |
| 信源发布日期 | 页面/文件的发布时间（YYYY-MM） | 无法确定 → 衰退风险默认"高" |

> "待验证假设 🟡🟠"不强制事实卡，但有 URL 与摘录时可上调置信度。

## 2. 核验分级（V0-V3）

核验等级作为**可选第九字段**追加在八字段标注之后（`├── 核验等级: V0/V1/V2/V3`），不破坏设定书 §4.2 格式：

| 等级 | 定义 | 对应动作 |
|------|------|---------|
| **V0** | 仅搜索结果摘要所得，未读取原文 | 默认起始等级；A/B 级信源条目须在 Phase 4 草稿前至少升至 V1 |
| **V1** | 已用 FetchURL（或等效手段）读取原文并摘录 | 单条事实可用的最低核验等级 |
| **V2** | 两个及以上独立信源交叉一致（转载同一源头不算独立） | 置信度可按 `quality-control.md` §4 上调 |
| **V3** | 数据库代检回传（SD-XX）或人工验证确认 | 最高等级，终稿条目原则上须达 V2 或 V3 |

## 3. 一票否决流程（虚假信息 veto）

### 3.1 否决触发条件（须满足其一，且必须有证据）

1. 信源 URL 失效，且替代检索无法找回同一事实的原始出处；
2. FetchURL 读取原文后发现**条目表述与原文不符**（断章取义、数据错误、张冠李戴）；
3. 信源本身被证实为伪造/仿冒页面；
4. 人工验证或外部 Agent 核验裁定为"证伪"（见 `../interface/agent-verification-api.md`）。

> **怀疑不构成否决**。仅因信息出乎意料、与其他条目不一致（未达矛盾报告标准）时，走置信度下调或矛盾报告流程，不走否决。

### 3.2 否决处置（立即执行）

1. 该条目正文中标记 `⛔ 已否决（VETO-XX）`，保留原文但不得再作为任何分析依据；
2. 登记失信记录表（见 §4）；
3. **影响追溯**：检索所有引用该条目的下游条目（SWOT 条目、综合评估、其他锚点），逐一标注"受 VETO-XX 影响"，重新评估置信度；以下游条目主要依据被否决时，该下游条目一并降级或剔除；
4. 该信源域名/账号列入"观察名单"，同来源其他条目核验等级上限降为 V1，直至人工复核。

### 3.3 否决的撤销

仅当新证据（找回原文、权威更正）证明否决有误时，由人工撤销，并在失信记录表中追加撤销记录。LLM 不得自行撤销否决。

## 4. 失信记录表

各 Phase 报告与 SWOT 草稿/终稿在出现否决时附本表：

| 否决编号 | 原条目编号 | 信源 | 否决原因 | 否决依据（证据） | 影响范围（受波及条目） | 处置 | 状态 |
|---------|-----------|------|---------|----------------|----------------------|------|------|
| VETO-01 | E-XX-XX | URL/名称 | 上述四类之一 | 具体证据描述 | 条目清单 | 剔除/降级 | 已否决/已撤销 |

- 否决编号全局连续（VETO-01 起，跨 Phase 接续，与 GAP/VT/SD 同规则）。
- 无否决事件的报告须写"无"，不得省略本节。

## 5. 外部 Agent 核验

核验任务可打包委派给外部 Agent（TRAE SOLO、Qoder Work、openClaw 等）执行独立核验，其裁决结果按本文件流程回写。接口规范、任务包 JSON Schema 与回导规则见 `../interface/agent-verification-api.md`。
