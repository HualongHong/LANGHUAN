# 合作模式谱系（Collab Mode Spectrum）

> 规范依据：设定书 §2（合作模式谱系五档）、§4（INDEP-CLAUSE）。定义团队间非排他性合作的五档模式、每档标配的独立性保障条款清单，以及草稿/终稿的模式建议边界。**独立性保障条款是 PCS 区别于 AVS 的核心交付增量。**

## 1. 谱系总览

团队间合作由浅入深呈五档谱系（耦合度递增，非排他性贯穿始终）：

```
成果引用与思路借鉴 → 数据/方法共享 → 联合发表 → 联合项目申报 → 人员互访/共建平台
  （档位 1）        （档位 2）      （档位 3）    （档位 4）      （档位 5）
```

- 五档均为**非排他性**安排：双方均保留与第三方并行合作的自由（多线并行是默认状态而非谈判结果）。
- 档位 ≥3（联合发表及以上）的合作**必须附独立性保障条款引用**（INDEP-CLAUSE 规则，见 `quality-control.md` §5），缺即违规。
- 档位不是单向晋升通道：四象限定位结论可触发**模式降档**（高互补 × 高风险时降档 + 加保障条款，见 `independence-boundary.md` §4）。

## 2. 五档详述

### 档位 1：成果引用与思路借鉴

- **定义**：零耦合合作。引用对方公开成果、借鉴思路与方法，无数据交换、无共著、无经费往来。
- **耦合特征**：无绑定；任何一方随时可单方面终止而不影响对方。
- **典型场景**：新方向调研、方法论移植、文献互引。
- **标配独立性保障条款**：无强制条款；仅需遵守常规学术引用规范。

### 档位 2：数据/方法共享

- **定义**：单向或双向共享数据、代码、实验方法或材料，**附使用边界与署名规则**。
- **耦合特征**：轻耦合；共享范围、二次使用权限、再分发限制须事先书面约定。
- **典型场景**：复用对方公开论文的配套数据、共享实验 protocol、互用各自采集的数据集做平行研究。
- **标配独立性保障条款**：**IC-01 数据主权**（数据归属、使用范围、再分发限制）、**IC-02 署名权**（使用方在何种成果中如何致谢/署名）。

### 档位 3：联合发表

- **定义**：双方人员实质贡献同一成果，共同署名发表；**作者排序与贡献说明预先约定**。
- **耦合特征**：中耦合；署名排序争议是学术合作最常见的摩擦点，须在投稿前约定。
- **典型场景**：联合实验、交叉验证、合著综述。
- **标配独立性保障条款**：**IC-02 署名权**（作者排序规则、通信作者安排、贡献声明模板）、**IC-03 后续独立申报权**（联合发表不妨碍双方各自以自身数据独立申报后续项目）、涉数据时加 **IC-01 数据主权**。

### 档位 4：联合项目申报

- **定义**：联合申报纵向/横向项目，事先约定**分工矩阵、经费分割、IP 归属框架**。
- **耦合特征**：高耦合；经费与任务绑定，但各自团队建制、人事、考核保持独立。
- **典型场景**：联合申报国家重点研发计划课题、联合承担行业横向项目。
- **标配独立性保障条款**：**IC-03 后续独立申报权**、**IC-04 学生培养归属**（参与学生的学籍、一作认定、毕业成果认定）、**IC-01 数据主权**（项目数据的分级归属）、**IC-02 署名权**（项目成果署名规则）。

### 档位 5：人员互访 / 共建平台

- **定义**：最深耦合：研究生联合培养/互访、共建实验室或数据平台、共享设备与机时。此类安排**必须附完整独立性保障条款与退出机制**。
- **耦合特征**：深耦合；涉及人员、空间、资产的跨团队流动，退出成本最高，退出规则必须事先约定。
- **典型场景**：联合培养研究生、共建野外台站/数据库/实验平台、长期访问学者计划。
- **标配独立性保障条款**：**五条款全配（IC-01 ~ IC-05）**，含退出与成果延续规则。

## 3. 独立性保障条款清单（IC-01 ~ IC-05）

五条款为全部档位的共用引用单元，Phase 4 模式建议中按编号引用（INDEP-CLAUSE）：

| 编号 | 条款 | 核心内容 |
|------|------|---------|
| **IC-01** | 数据主权 | 数据/材料/代码的归属界定；共享范围与使用边界；二次使用与再分发限制；项目结束后数据的留存与销毁规则 |
| **IC-02** | 署名权 | 作者排序规则（按贡献还是按字母）、通信作者安排、贡献声明模板；使用对方数据/方法时的致谢与引用义务 |
| **IC-03** | 后续独立申报权 | 合作不妨碍双方各自独立申报项目与发表独立成果；共同成果的知识产权分割框架；一方退出后既有成果的继续使用规则 |
| **IC-04** | 学生培养归属 | 参与学生的学籍归属、第一作者认定、毕业论文成果认定；联合培养学生的导师认定与答辩安排 |
| **IC-05** | 退出与成果延续规则 | 任一方退出的提前通知期；退出时已产生成果的处理；共建平台/数据的后续运营与访问权；合作关系终止后的成果引用义务 |

## 4. 终稿模式建议的格式要求

终稿的合作模式匹配建议须包含：

- **模式选项**：从五档中选取（可主选 + 备选），注明目标档位编号；
- **推荐度**：排序 + 理由（**必须引用具体 SWOT 条目编号支撑**，并说明档位选择的四象限依据，见 `independence-boundary.md` §3）；
- **保障条款引用**：档位 ≥3 时必须按编号引用 §3 条款清单（如"标配 IC-02 + IC-03"），不得笼统写"附保障条款"；
- **实施路径**：分阶段时间表（先行低档位试点 → 验证后再升档是默认推荐路径）。

## 5. 草稿与终稿的边界

| 内容 | 第一轮草稿（LLM） | 第二轮终稿（人工修正） |
|------|------------------|----------------------|
| SWOT 条目 + 标注 | ✅ | ✅（修正后） |
| 信息缺口追踪表 | ✅ | ✅（更新） |
| 置信度 | 初标 | 提升追踪 |
| 四象限定位（互补强度 × 独立性风险） | 仅输出定位所需锚点，**不输出定位结论** | ✅ |
| 合作模式匹配建议（档位 + 保障条款） | ❌ 禁止 | ✅（人工形成） |

> 违反上表边界的草稿视为不合格，须退回重做（ADAPT-RULE 告警，见 `quality-control.md` §5）。
