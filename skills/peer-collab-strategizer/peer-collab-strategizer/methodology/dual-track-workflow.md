# 双轨制工作流（Dual-Track Workflow）

> 规范依据：设定书 §1、§2。复用 AVS 双轨制骨架，定义 LLM 轨道与人工轨道的职责分界及四阶段执行流程。LLM 轨 = 公开信息锚点；人工轨 = 团队意愿 / 资源实情。

## 铁律

> **LLM 不做团队适配度结论与独立性裁决，只做合作线索发现。**

团队适配判断（双方是否适配、以何种模式合作）与独立性边界划定（哪些可以给、哪些不能给）只能由人工在两轮迭代后形成。LLM 的全部产出均为"锚点 + 可验证假设"。

## 与 AVS 的分工对照

| | AVS（已有） | PCS（本技能） |
|---|---|---|
| 主体 | 企业 × 高校/科研机构 | 团队（PI 课题组）× 团队 |
| 合作性质 | 排他性（独家许可→合资公司梯度） | **非排他性**（多线并行、互不绑定） |
| 评估轴 | 企业需求强度 × 机构供给能力 | 互补性 × 独立性边界 × 贡献杠杆 |
| 数据侧重点 | 企业战略/专利/ESG、机构平台 | 学术成果谱系（ORCID 等）、团队生态位 |
| 产出 | SWOT × 排他性报告 | SWOT × 合作模式报告（附独立性保障条款） |

## 双轨制结构

```
 LLM轨道                        人工轨道
┌──────────┐                  ┌──────────┐
│ 公开信息  │                  │ PI 访谈  │
│ 检索整合  │─── 锚点 ───→    │ 团队意愿  │
│ 假设生成  │   ←── 验证 ──   │ 资源实情  │
└──────────┘                  └──────────┘
     │                              │
     └──────────────┬───────────────┘
                    ↓
            ┌──────────────┐
            │ SWOT × 合作模式 │
            │  终稿报告        │
            └──────────────┘
```

- **LLM 轨道**：公开信息搜集（ORCID 公共 API、OpenAlex、机构官网、基金公示等）→ 信息整合 → 假设生成。产出锚点（可验证事实或推断），作为人工深挖的起点。
- **人工轨道**：PI 访谈、团队内部数据、意愿与诉求确认。聚焦验证 LLM 产出的关键假设，补充公开信息盲区（在研方向、经费余量、学生负荷等）。

## 四阶段流程

```
Phase 1 ────→ Phase 2 ────→ Phase 3 ────→ Phase 4
本团队锚点画像 目标团队锚点画像 学术生态位扫描   SWOT × 合作模式整合
(LLM 100%)   (LLM 100%)    (LLM 100%)    (LLM 草稿 → 人工两轮迭代)
                ↓
        第一轮：LLM 草稿
        第二轮：人工修正 → 终稿
```

| 阶段 | 内容 | 轨道占比 | 输出物 | 模板 |
|------|------|---------|--------|------|
| Phase 1 | 本团队画像（Self） | LLM 100%（内部材料由人工喂入） | 本团队画像报告 | `templates/phase1-self.md` |
| Phase 2 | 目标团队画像（Peer） | LLM 100%（ORCID/公开源锚点） | 目标团队画像报告 | `templates/phase2-peer.md` |
| Phase 3 | 学术生态位扫描（Landscape） | LLM 100% + SD 委托单 | 生态位扫描报告 | `templates/phase3-landscape.md` |
| Phase 4 | SWOT × 合作模式整合 | LLM 草稿 → 人工两轮迭代 | SWOT 草稿 → 终稿 | `templates/phase4-swot-draft.md` / `phase4-swot-final.md` |

- Phase 1 与 Phase 2 对称，可**并行执行**。
- Phase 3 依赖 Phase 1/2 确定的本团队-目标团队对及技术方向。
- Phase 4 两轮迭代：第一轮 LLM 独立完成草稿；第二轮人工修正后形成终稿。

## 执行流程（Step 0-5）

| 步骤 | 内容 | 预计耗时 |
|------|------|---------|
| Step 0 | 初始化：输入本团队名称、目标团队名称（含 PI 及核心成员 ORCID iD 列表）、技术方向；设置信源偏好与人工验证资源安排 | — |
| Step 1 | 并行执行 Phase 1 + Phase 2（LLM 轨道）；Phase 1 的内部材料由人工整理喂入 | 1-2 小时（取决于信息密度） |
| Step 2 | 执行 Phase 3（LLM 轨道）：同领域团队地图、生态位重叠/空白、并行冲突登记 | 1-2 小时 |
| Step 3 | 产出 SWOT 草稿（LLM 轨道）：基于 Phase 1-3 全部锚点，自动标注置信度、缺口、假设 | 30 分钟 |
| Step 4 | 人工验证（人工轨道）：按紧急度排序验证假设（重点：D3-D6 类），修正 SWOT 各条目 | 2-5 个工作日（取决于访谈资源） |
| Step 5 | 产出 SWOT 终稿 + 合作模式建议：合并 LLM 草稿与人工验证结果，输出合作模式匹配建议（谱系档位 + 独立性保障条款引用） | 1 小时 |

## 职责分界速查

| 事项 | LLM | 人工 |
|------|-----|------|
| 公开信息搜集与结构化（ORCID/OpenAlex/官网/公示） | ✅ | — |
| 信源评级与置信度初标 | ✅ | 复核 |
| 假设生成 + 验证路径建议 | ✅ | — |
| 团队适配度结论与独立性裁决 | ❌ 禁止 | ✅ |
| D3/D4/D5/D6 类数据获取 | 仅公开弱锚点 | ✅ 主责 |
| 本团队内部材料（负荷/档期/经费余量） | 由人工喂入后结构化 | ✅ 主责 |
| 低置信度（<50%）条目处置 | 标记"不可用" | ✅ 验证或剔除 |
| 付费/账号制数据库检索（CNKI/WoS/Scopus 等） | 输出检索式与筛选条件（SD-XX 委托单，见 `quality-control.md` §3.1） | ✅ 执行代检并回传 |
| ResearchGate 页面核验 | ❌ 禁止自动化抓取（违反 ToS） | ✅ 人工 FetchURL 核对主页 |
