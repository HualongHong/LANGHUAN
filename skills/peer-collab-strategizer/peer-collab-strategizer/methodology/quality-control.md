# 质量管控机制（Quality Control）

> 规范依据：设定书 §4（条目、编号与质量管控）。包含信源可信度评级、条目八字段标注格式、事实卡与核验分级、人工介入触发规则、lint 规则清单、信息缺口追踪与一票否决。**本文件合并承载 AVS `fact-verification.md` 的事实卡/V0-V3/否决流程内容（PCS 不设独立 fact-verification 文件）。**

## 1. 信源可信度评级

| 等级 | 定义 | 示例 |
|------|------|------|
| 🟢 A | 官方披露 | ORCID 官方记录、机构官网教师主页、基金委/科技部立项公示、政府批复、期刊正式发表版本 |
| 🟡 B | 权威第三方 | OpenAlex/Semantic Scholar 聚合数据、权威学术媒体报道、学会官方发布、预印本平台 |
| 🟠 C | 间接推断 | 招聘 JD、会议议程与讲者信息、新闻推测、ResearchGate 页面线索（未人工核对前） |
| 🔴 D | 同类类比 | 领域均值替代、以其他团队公开数据对目标团队的镜像推断 |

使用规则：

- 每条锚点/SWOT 条目必须标注信源等级（见 §2 标注格式）。
- 信源等级是置信度初标的首要依据；同一事实有多个独立信源交叉验证时可上调置信度。
- D 级信源条目必须显著标注"类比推断"，且默认 `需人工验证: 是`。
- **ResearchGate 无官方公开 API，自动化抓取违反其 ToS**：RG 页面仅作人工核验辅助渠道（人工/宿主 Agent 用 FetchURL 核对主页），任何 RG 来源条目在人工核对前最高 C 级，核对后按内容性质重标。

## 2. 条目标准标注格式（强制，PCS 八字段）

所有锚点条目与 SWOT 条目必须使用以下八字段标注格式：

```
编号-维度-序号: [内容描述]
├── 信源等级: A/B/C/D
├── 置信度: XX%
├── 数据类别归属: D1-D6
├── 互补性贡献: ★☆☆☆☆ ~ ★★★★★
├── 独立性影响评估: 低/中/高
├── 需人工验证: 是/否
├── 验证路径: [具体方式]
└── 时效性/衰退风险: YYYY-MM / 高/中/低
```

字段说明：

| 字段 | 取值 | 说明 |
|------|------|------|
| 编号 | `[报告前缀]-[维度]-[序号]` | 报告前缀：`S-`（本团队）/ `P-`（目标团队）/ `L-`（生态位）/ `SWOT-`（综合），如 `S-供给-01`、`P-成果-01`、`SWOT-S-02` |
| 信源等级 | A/B/C/D | 评级标准见 §1 |
| 置信度 | 0-100% | 基于信源等级与交叉验证数量；<50% 触发"不可用"规则 |
| 数据类别归属 | D1-D6 | 六类数据框架，见 `six-data-types.md` |
| 互补性贡献 | ★1-5 | 该条目对互补性判断的边际贡献 |
| 独立性影响评估 | 低/中/高 | 判据见 `independence-boundary.md` §3；`高` 的条目必须人工验证 |
| 需人工验证 | 是/否 | D3/D4/D5/D6 类条目默认"是" |
| 验证路径 | 具体方式 | 访谈 / 内部文档 / 专家咨询 / 人工 FetchURL 核对 / 数据库代检（SD-XX）等 |
| 时效性/衰退风险 | YYYY-MM / 高/中/低 | 信息的有效基准月份；随时间失效速度（人事变动类为高） |

**完整示例条目（S- 前缀，本团队侧）**：

```
S-供给-01: [本团队已建成某领域实验数据集，覆盖 2018-2025 年 12 个站点观测，
          数据字典与质量控制文档齐全；数据尚未对外公开发布]
├── 信源等级: A
├── 置信度: 85%
├── 数据类别归属: D4
├── 互补性贡献: ★★★★☆
├── 独立性影响评估: 中
├── 需人工验证: 是
├── 验证路径: PI 确认共享范围意愿与数据脱敏要求（内部材料由人工喂入后复核）；
             若对外共享须补 IC-01 数据主权条款约定
└── 时效性/衰退风险: 2026-09 / 低
```

**完整示例条目（P- 前缀，目标团队侧）**：

```
P-成果-01: [目标团队 PI 及 5 名核心成员经 ORCID 聚合，2020-2026 年共发表论文 47 篇，
           其中与本团队技术方向高度相关的 11 篇，主题聚类显示主线为"多尺度耦合模拟"，
           近三年年均产出 8 篇且持续上升]
├── 信源等级: A
├── 置信度: 80%
├── 数据类别归属: D1
├── 互补性贡献: ★★★★★
├── 独立性影响评估: 低
├── 需人工验证: 是
├── 验证路径: 人工 FetchURL 核对 ORCID 记录原文（pub.orcid.org/v3.0/{iid}/record，
             检索日期 2026-09-XX）；以 OpenAlex 交叉验证作者-机构映射，
             差异项登记 GAP 转人工；部分学者无 ORCID iD 的覆盖缺口按设定书 §7.2 处理
└── 时效性/衰退风险: 2026-09 / 中
```

## 3. 事实卡与核验分级（V0-V3）

### 3.1 事实卡标准（精细度基线）

每条"已确认事实 🟢"必须构成一张**事实卡**，包含四要素：

| 要素 | 要求 | 缺失处置 |
|------|------|---------|
| 信源 URL | 真实可访问，指向原始页面而非聚合转载 | 无法给出 URL → 不得入"已确认事实"，降级为待验证假设 |
| 原文摘录 | 从信源页面摘录的关键句（≤100 字），置于 `验证路径` 或条目附注中 | 无摘录视为未读原文，核验等级不得高于 V0 |
| 检索日期 | YYYY-MM-DD | 缺失 → 时效性字段无效 |
| 信源发布日期 | 页面/文件的发布时间（YYYY-MM） | 无法确定 → 衰退风险默认"高" |

> "待验证假设 🟡🟠"不强制事实卡，但有 URL 与摘录时可上调置信度。

### 3.2 核验分级（可选第九字段）

核验等级作为**可选第九字段**追加在八字段标注之后（`├── 核验等级: V0/V1/V2/V3`），不破坏 §2 格式：

| 等级 | 定义 | 对应动作 |
|------|------|---------|
| **V0** | 仅搜索结果摘要所得，未读取原文 | 默认起始等级；A/B 级信源条目须在 Phase 4 草稿前至少升至 V1 |
| **V1** | 已用 FetchURL（或等效手段）读取原文并摘录 | 单条事实可用的最低核验等级 |
| **V2** | 两个及以上独立信源交叉一致（转载同一源头不算独立） | 置信度可按 §8 上调 |
| **V3** | 数据库代检回传（SD-XX）或人工验证确认 | 最高等级，终稿条目原则上须达 V2 或 V3 |

## 4. 人工介入触发规则

| # | 触发条件 | 触发动作 | 默认角色 |
|---|---------|---------|---------|
| 1 | 任一 SWOT 条目置信度 < 50% | 标记为"不可用"，自动纳入人工验证清单 | 研究员 |
| 2 | 涉及团队适配度核心判断 | LLM 禁止输出结论，仅输出"假设 + 验证路径"（ADAPT-RULE） | 研究员 + 领域专家 |
| 3 | 两个 A 级信源信息矛盾 | 暂停该维度分析，生成"矛盾报告" | 研究员 |
| 4 | 某维度可获取信息占比 < 30% | 生成"信息缺口报告"，标记为盲区 | 研究员 |
| 5 | D3/D4/D5/D6 类条目（D3456-VERIFY） | **一律强制人工验证**，LLM 仅输出公开弱锚点 | 研究员/PI |
| 6 | Phase 4 合作模式档位 ≥3 的条目未附独立性保障条款引用 | INDEP-CLAUSE 违规，ERROR，退回修正 | 研究员 |
| 7 | 触及法律合规边界（数据出境、伦理、经费办法） | 强制转入人工合规核查，模式建议标注"合规核查前置" | 科研管理/法务 |
| 8 | 涉及大型基础设施类成果（数据库/平台/标准/联盟） | 强制多源归属核验，标注主导方与参与方；禁止"作者单位 = 成果归属"推断；归属未核验前置信度 ≤75% 且 `需人工验证: 是` | 研究员 |

矛盾报告（规则 3）须包含：矛盾双方信源、各自原文摘录、矛盾点描述、建议核查方式。

## 5. lint 规则清单

对 Phase 1-4 全部报告执行的自动合规检查（M3 脚本 `lint_report.py` 落地，此处为规则定义）：

| 规则 | 级别 | 定义 |
|------|------|------|
| FIELD-8 | ERROR | 条目缺八字段任一字段 |
| FACT-CARD | ERROR | "已确认事实"条目事实卡四要素不全（无 URL 者必须降级） |
| CONF-50 | WARN | 置信度 < 50% 的条目未标记"不可用"或未纳入 VT 清单 |
| NUM-DUP | ERROR | GAP/VT/SD/VETO 编号重复或跳号（全局连续） |
| VETO-SECTION | ERROR | 报告缺"失信记录表"节（无否决事件时须写"无"） |
| **D3456-VERIFY** | ERROR | 数据类别为 D3/D4/D5/D6 的条目 `需人工验证` 非"是" |
| **ADAPT-RULE** | WARN | 草稿中出现"团队适配度结论/合作模式推荐"类表述且同行无否定词 → 告警并退回（铁律：`dual-track-workflow.md`） |
| **INDEP-CLAUSE** | ERROR | Phase 4 中合作模式档位 ≥3（联合发表及以上）的条目未附 IC-01~IC-05 条款引用 |

## 6. 信息缺口追踪表（GAP-XX）

各 Phase 报告与 SWOT 草稿/终稿均须附本表：

| 缺口编号 | 所属维度 | 期望信息 | 缺失原因 | 替代方案 | 对 SWOT 影响 |
|---------|---------|---------|---------|---------|-------------|
| GAP-XX | D1-D6 | 具体描述 | 未公开/需内部 | 领域类比/等待人工 | 高/中/低 |

使用规则：

- 缺口编号全局唯一，按 `GAP-01`、`GAP-02`…… 顺序分配，跨 Phase 连续编号。
- 每个缺口必须给出替代方案（领域类比 / 等待人工 / 人工代检），无替代方案时注明"阻塞"。缺失原因为"需数据库账号（付费墙）"时，替代方案一律为"人工代检"，并须同时生成检索委托单（见 §6.1）。
- 终稿中须更新本表：已被人工验证填补的缺口标记"已闭合"，仍开放的缺口进入局限性声明。

## 6.1 人工检索委托单（SD-XX，付费墙处置）

**触发条件**：检索需要付费/账号制数据库（CNKI、万方、Web of Science、Scopus 等）而 LLM 无法直接访问时。

**铁则**：

1. **不得放弃该维度，也不得编造或用低质类比冒充**。检索不到 ≠ 信息不存在——登记 GAP（缺失原因 = "需数据库账号"），同时生成检索委托单 SD-XX，由人类执行代检并回传。
2. SD-XX 全局连续编号（跨 Phase 接续），每单必须关联对应的 GAP-XX 与 VT-XX；关联 VT 任务的验证路径标注"数据库代检（SD-XX）"。
3. **检索条件必须具体到人类无需追问即可执行**：给出数据库原生检索式与全部筛选条件。
4. 回传结果按其性质重新标定信源等级（数据库检索结果通常为 A/B 级），更新对应锚点置信度，并将 GAP 标记"已闭合"。

**委托单格式（强制）**：

```
SD-XX: [委托标题，如"目标团队 PI 论文清单 WoS 代检"]
├── 关联缺口: GAP-XX
├── 关联验证任务: VT-XX
├── 目标数据库: [CNKI / Web of Science / Scopus / 万方 / 其他]
├── 检索目的: [对应哪个维度的哪条假设，期望回答什么问题]
├── 检索式: [数据库原生语法，逐库给出；示例见下]
├── 筛选条件: [时间范围 / 文献类型 / 学科分类 / 语种 / 作者机构等]
├── 排序与数量: [如"按被引降序取前 50 条"]
├── 期望输出: [字段清单（标题/作者/机构/年份/被引/DOI 等）+ 交付格式（Excel/RIS/EndNote/截图）]
└── 状态: 待执行 / 已回收（回收日期 + 信源等级重标结果）
```

**检索式示例**（供 LLM 参照生成，须按目标替换）：

- Web of Science：`AU=(张三) AND AD=(某大学) AND TS=("multi-scale" OR "coupled simulation")`，Timespan 2020-2026，Document Type: Article/Review
- CNKI 专业检索：`AU='张三' AND AF='某大学' AND SU=('多尺度'+'耦合模拟')`，时间 2020-2026，来源类别限定核心期刊/CSCD

## 7. 一票否决流程（虚假信息 veto）

### 7.1 否决触发条件（须满足其一，且必须有证据）

1. 信源 URL 失效，且替代检索无法找回同一事实的原始出处；
2. FetchURL 读取原文后发现**条目表述与原文不符**（断章取义、数据错误、张冠李戴）；
3. 信源本身被证实为伪造/仿冒页面；
4. 人工验证或外部 Agent 核验裁定为"证伪"（见 `../interface/agent-verification-api.md`）。

> **怀疑不构成否决**。仅因信息出乎意料、与其他条目不一致（未达矛盾报告标准）时，走置信度下调或矛盾报告流程，不走否决。

### 7.2 否决处置（立即执行）

1. 该条目正文中标记 `⛔ 已否决（VETO-XX）`，保留原文但不得再作为任何分析依据；
2. 登记失信记录表（见 §7.3）；
3. **影响追溯**：检索所有引用该条目的下游条目（SWOT 条目、综合评估、其他锚点），逐一标注"受 VETO-XX 影响"，重新评估置信度；以下游条目主要依据被否决时，该下游条目一并降级或剔除；
4. 该信源域名/账号列入"观察名单"，同来源其他条目核验等级上限降为 V1，直至人工复核。

### 7.3 否决的撤销

仅当新证据（找回原文、权威更正）证明否决有误时，由人工撤销，并在失信记录表中追加撤销记录。LLM 不得自行撤销否决。

### 7.4 失信记录表

各 Phase 报告与 SWOT 草稿/终稿在出现否决时附本表：

| 否决编号 | 原条目编号 | 信源 | 否决原因 | 否决依据（证据） | 影响范围（受波及条目） | 处置 | 状态 |
|---------|-----------|------|---------|----------------|----------------------|------|------|
| VETO-01 | P-XX-XX | URL/名称 | 上述四类之一 | 具体证据描述 | 条目清单 | 剔除/降级 | 已否决/已撤销 |

- 否决编号全局连续（VETO-01 起，跨 Phase 接续，与 GAP/VT/SD 同规则）。
- 无否决事件的报告须写"无"，不得省略本节。

## 8. 置信度标定参考

置信度 = f（信源等级, 交叉验证数量, 时效性）。参考基准：

| 情形 | 建议初始置信度 |
|------|--------------|
| 单一 A 级信源，近期 | 70-85% |
| 多个独立 A/B 级信源交叉一致 | 85-95% |
| 单一 B 级信源 | 60-75% |
| C 级间接推断 | 40-60% |
| D 级同类类比 | 20-40%（多数触发 <50% 规则） |
| 信息距今 > 12 个月 | 在基础上降 10-20 个百分点 |

> 上表为初标参考，最终置信度由人工验证环节确认。终稿须记录各条目置信度修正轨迹（修正前 → 修正后）。

## 9. 外部 Agent 核验

核验任务可打包委派给外部 Agent（TRAE SOLO、Qoder Work、openClaw 等）执行独立核验，其裁决结果按 §7 流程回写。接口规范、任务包 JSON Schema 与回导规则见 `../interface/agent-verification-api.md`。
