# 六类数据框架（Six Data Types）

> 规范依据：设定书 §3。PCS 将团队间合作评估所需的全部数据归为六类，每类明确定义 LLM 可获取性边界。**所有锚点条目必须标注其数据类别归属（D1-D6）。** D3-D6 全部强制人工验证（D3456-VERIFY 规则，见 `quality-control.md`）。

## 总览

| 编号 | 数据类别 | 核心问题 | LLM 可获取性 | 对合作判断的独力贡献 |
|------|---------|---------|-------------|---------------------|
| **D1** | 公开事实（论文/项目/任职） | 双方各自有什么、做过什么？ | 🟢 大部分可获取（ORCID、OpenAlex、基金公示、机构官网） | 🟢 中（能列谱系，不能判互补深度） |
| **D2** | 公开但需解读（合作风格/学术品味） | 对方是怎样合作的？ | 🟡 部分可获取（共著模式、致谢惯例、公开评议），需人工解读 | 🟡 低-中（看到形式，看不到默契） |
| **D3** | 在研方向与经费余量 | 对方正在做什么、还能接多少？ | 🔴 几乎不可获取（仅公开立项线索） | 🔴 极低 |
| **D4** | 团队内部实情（学生负荷/设备档期/PI 意向） | 对方还有没有余力真合作？ | 🔴 不可获取（纯内部信息） | 🔴 极低 |
| **D5** | 隐性诉求（署名敏感度/长期意愿） | 对方真正想要什么？ | 🔴 几乎不可获取（仅公开画像） | 🔴 极低 |
| **D6** | 冲突风险（与第三方的优先承诺） | 对方是否已被他人锁定？ | 🔴 不可获取（仅公开合作痕迹） | 🔴 极低 |

## 分类详述

### D1 公开事实（论文 / 项目 / 任职）

- **核心问题**：双方团队各自产出了什么、承担了什么项目、人员结构如何？成果谱系的主线与活跃期是什么？
- **LLM 可获取性**：大部分可获取。ORCID 公共 API（pub.orcid.org/v3.0，免 key）聚合 PI 及核心成员 works（标题/年份/DOI/类型/合作者），OpenAlex 补团队级主题聚类与引用影响，基金委/科技部立项公示、机构官网教师主页可覆盖任职与项目层面。
- **边界**：LLM 能列出成果清单与主题聚类，但**不能判断单项成果的合作价值与互补深度**——价值判断须交人工（领域专家）。
- **典型信源**：ORCID 记录（A）、OpenAlex（A/B）、NSFC/科技部立项公示（A）、机构官网主页（A/B）。论文数据库（CNKI、Web of Science、Scopus 等）存在账号墙，LLM 无法直接访问时按 `quality-control.md` §3.1 生成检索委托单 SD-XX 交人工代检。

### D2 公开但需解读（合作风格 / 学术品味）

- **核心问题**：目标团队的合作风格如何？惯常共著模式（大联盟式 vs 小圈子式）、署名排序惯例、致谢与利益声明习惯、公开学术评议的品味倾向是什么？
- **LLM 可获取性**：部分可获取。共著网络、通信作者分布、致谢文本、公开评论可见。
- **边界**：LLM 能看到合作的**形式**（和谁合著、怎么署名），看不到合作的**默契与口碑**（是否好合作、是否拖延、数据是否靠谱）——深度须人工访谈验证。
- **典型信源**：ORCID/OpenAlex 共著关系（A/B）、论文致谢与作者贡献声明（A）、学术社区口碑（C）。

### D3 在研方向与经费余量

- **核心问题**：目标团队**正在做但未发表**什么？在研项目周期与经费余量还能承接多少新合作？
- **LLM 可获取性**：几乎不可获取。只能触及公开立项（基金委批准项目）与预印本线索，在研未发表方向、经费执行进度、结余余量均属内部信息。
- **边界**：真实的在研布局与经费余量**必须人工获取**（PI 直接交流或共同熟人侧面了解）。
- **典型信源**：已批准项目公示（A，仅作弱锚点）、预印本平台（B/C）、招聘启事中的项目方向（C），均须显著标注不确定性。

### D4 团队内部实情（学生负荷 / 设备档期 / PI 意向）

- **核心问题**：目标团队（及本团队）的研究生负荷是否饱和？共享设备档期是否排得开？PI 对新增合作的真实态度如何？
- **LLM 可获取性**：不可获取。研究生人数与年级结构、设备机时、PI 意向均为团队内部信息。
- **边界**：此类信息决定合作能否落地，**必须人工获取**；LLM 禁止据此下团队适配度结论。
- **典型信源**：无公开信源；仅能通过访谈获得（验证路径一律写访谈对象类型）。

### D5 隐性诉求（署名敏感度 / 长期合作意愿）

- **核心问题**：PI 对署名排序的敏感度如何？期望的是一次性合作还是长期伙伴关系？对学生一作的坚持程度？
- **LLM 可获取性**：几乎不可获取。仅能构建公开画像（署名历史、公开讲话、学术轨迹）。
- **边界**：隐性诉求是合作模式选择的关键变量（尤其档位 ≥3 的联合发表/联合申报），只能由人工通过访谈/学术圈侧面了解获取。LLM 输出限于"公开画像 + 待验证假设"。
- **典型信源**：历史署名模式（B/C，仅作弱锚点）、公开演讲/采访（B/C）。

### D6 冲突风险（与第三方的优先承诺）

- **核心问题**：目标团队是否已对第三方作出优先承诺（如同一数据的优先共享、同一方向的排他性联合申报、学生的联合培养占用）？
- **LLM 可获取性**：不可获取。仅能观察到公开合作痕迹（与谁常合著、与谁常联合申报）。
- **边界**：多线并行 ≠ 无冲突——公开合作痕迹只是线索，真实承诺须人工核验；**LLM 禁止据此下适配度结论**。
- **典型信源**：公开联合申报与合著记录（A/B，仅作线索）、Phase 3 并行冲突登记（见 `templates/phase3-landscape.md`）。

## 使用规则

1. 每条锚点/SWOT 条目必须标注 `数据类别归属: D1-D6`（标注格式见 `quality-control.md` §1）。
2. **D3、D4、D5、D6 类条目一律默认 `需人工验证: 是`**（D3456-VERIFY 规则，`quality-control.md` §2）——这四类决定了第一轮产出必然是**假设驱动**的。
3. 某维度可获取信息占比 < 30% 时，按质量管控规则生成"信息缺口报告"（见 `quality-control.md`）。
4. 凡涉及付费/账号制数据库的维度，检索不到不等于信息不存在，须登记 GAP 并附 SD-XX 委托单（见 `quality-control.md` §3.1）。
